# GDD — 「오르답」 (가제) : 정답을 밟고 오르는 무한 학습 계단

작성 2026-09-04 · game-builder v7.1 Phase 1 · 상태: **승인 대기(코드 0줄)**
수치 정본 = `tools/probe-grid.mjs`(게임 코어를 직접 import 하는 프로브) 출력. §1-4-2 표는 `tools/sync-gdd-table.mjs` 가 생성하고 `--check` 가 어긋남을 막는다(손계산 전사 금지). 법무 근거 = `docs/RESEARCH.md` §3.

## 1-1. 게임 개요
- **이름(가제)**: 오르답 — "오르다 + 답". 대안: 「답계단」「스텝답」. 배포 전 KIPRIS 상표 검색 필수(사용자 항목).
- **장르**: 즉답 학습 × 엔드리스 계단 오르기 아케이드 (2D, 세로 화면)
- **플랫폼**: 웹(모바일 브라우저 1순위, 데스크톱 겸용) → PWA → Capacitor(iOS/Android) 순
- **타겟**: 초등 2~6학년(구구단 = 2학년, 영단어 = 3~6학년), 부모·교사 보조 사용
- **한 줄 컨셉**: 위로 갈라지는 발판마다 답이 적혀 있다. **맞는 답을 밟아야만 한 층 오른다.** 틀리면 발판에 금이 가고, 시간이 다하면 발판이 사라진다.
- **세계관**: 구름 위 «지식의 탑». 층마다 다른 하늘(새벽→낮→노을→별밤)로 오르며 스킨 캐릭터를 수집한다. 스토리 텍스트 최소(아이가 읽지 않고 바로 시작).
- **상업 모델(v1)**: 웹 무료 + 앱스토어 **일회성 유료(₩3,900 안)** 또는 학교·학원 단체 라이선스. **광고 SDK·인앱 결제·계정 없음**(아동 개인정보 0 원칙). 결제 도입은 v2 중대 변경으로 별도 FULL 검증.

## 1-2. 코어 루프
```
[문제 카드 표시] → [갈래 발판 중 정답 탭] → [한 층 상승·코인] → [층↑: 타이머 단축·3갈래 등장] → 반복
      ↑                                 ↓ 오답/시간초과 → 하트 −1, 정답 발판 하이라이트(교정)
      └──── 하트 0 → 게임오버 → 결과(층·정답률·오답노트) → «한 판 더»(2탭 이내)
```
- **학습 = 진행의 1차 자원**(L-041): 층을 올리는 유일한 방법은 정답. 시간은 «벽», 정답은 «열쇠».
- **메타 루프**: 코인 → 스킨·탑 테마 해금(코스메틱만) / 마스터리 맵(구구단 단별 ★, 단어 박스 진행도 `●●○○`) / 일일 미션 3개 / 최고 층 기록(로컬).
- **세션 길이**: 한 런 60~180초(정답률 90% 봇 기준 약 98문항·중앙값 80층). **앱 첫 화면 기준** 첫 문제까지 총 **3탭 이내**(과목 카드 1 + 범위 확인 1 + 시작 1 — D1 과 같은 기준점).
- **한 판 더 장치**: 게임오버 시 «최고 기록까지 N층» 표시, 재시작 버튼 2초 내 활성, 오답 1개를 카드로 보여주고 «이번엔 이거 맞히기» 미션 자동 부여.

## 1-3. 핵심 메카닉 상세
### 1-3-1. 조작
| 입력 | 데스크톱 | 모바일 |
|---|---|---|
| 왼쪽 갈래 | ← 또는 A | 화면 왼쪽 1/3 탭 |
| 가운데 갈래(3갈래 시) | ↑ 또는 W | 화면 가운데 1/3 탭 |
| 오른쪽 갈래 | → 또는 D | 화면 오른쪽 1/3 탭 |
| 일시정지 | Esc | 상단 우측 버튼(44px+) |
- 입력은 «발판이 확정된 뒤»부터만 받는다. 활성화 이전·해결 국면·타임아웃 이후의 입력은 **버퍼링 없이 무시**한다 — 선택지는 활성화 순간에 처음 보이므로 그 전의 탭은 «보지 않은 문제에 대한 답»이 된다(2026-09-04 교차검증 3계열 합의). 키 자동 반복(`e.repeat`)도 무시한다. 문항당 판정 **정확히 1회**.

### 1-3-2. 문항·판정
- 문제 카드가 상단에 뜨고, 같은 순간 갈래 발판 위에 선택지가 찍힌다. 정답률 판정은 **탭한 갈래 = 정답 갈래** 뿐이다(L-042: 우연 접촉이라는 개념 자체가 없다).
- **정답**: 캐릭터가 그 발판으로 점프(트윈 220ms, 착지 스쿼시), 층 +1, 코인 +1, 스트릭 +1(스트릭이 10의 배수가 되면 코인 +5·하트 +1), 정답 SFX.
- **오답**: 밟은 발판에 금이 가며 캐릭터 헛디딤(280ms), 하트 −1, 스트릭 0, **정답 발판 0.8초 하이라이트 + 정답 읽어주기 텍스트**(교정 피드백). **하트가 남아 있으면** 정답 발판으로 자동 이동해 다음 문항 진행(층은 오르지 않음). **하트가 0이면** 하이라이트 후 자동 이동·다음 문항 없이 결과 화면으로 간다.
- **시간초과** = 오답과 동일 처리(발판이 흐려지며 사라지는 연출).
- **하트**: 시작 3, 최대 3, **스트릭 10마다 +1**. 0 → 게임오버. 🚫 코인/광고 부활 없음(교육 게임 부활 금지 룰). 부활 대신 «오답노트 3문제 연속 정답 → 1회 부활»은 v2 검토 항목.

### 1-3-4. 정답 위치 — 위치 덱 (HARD, L-109)
정답 위치는 셔플이 아니라 **덱**으로 고른다. 갈래 수별로 **독립 덱** 운용(30~59층 혼합 구간에서 2갈래 문항은 2갈래 덱만, 3갈래 문항은 3갈래 덱만 뽑는다): 2갈래 덱 `[L,L,L,R,R,R]`, 3갈래 덱 `[L,L,C,C,R,R]`.
- **카운팅 방어**: 덱을 끝까지 소진하지 않는다 — 잔여 2장 이하가 되면 새 덱을 섞어 **잔여분과 합쳐** 계속 뽑는다(마지막 위치가 이력만으로 확정되는 순간을 없앤다).
- **병합 불변식**: 병합 직후 «직전 출제 위치 이력 + 새 덱 순서»에서 같은 위치 4연속이 생기면 재셔플(최대 20회, 그래도 생기면 4번째 카드를 다른 위치와 교환). D8 표본은 병합 경계를 반드시 포함한다(덱 길이의 10배 이상 연속 출제).
- 게이트 ① `check-answer-balance.mjs` **과목별·갈래 수별** 실행, 종료코드 0. ② **위치 이력 공격 봇**(문제를 안 보고 지난 위치 이력만으로 가장 유력한 위치를 고르는 p=0 봇)의 중앙값 층이 균등 p=0 봇 중앙값 +1 이하(D8b).

### 1-3-5. 오답(distractor) 생성 규칙
- **구구단**: 정답 a×b 에 대해 후보 = {a×(b±1), (a±1)×b, **(a±1)×(b∓1)**} ∪ **흔한 오류 사전**(`gugudan-common-errors.json`, 예: 7×8→54, 6×7→48, 8×7→54, 9×6→56) 중 정답과 다른 값. 우선순위 = 흔한 오류 사전 > 교차 후보 > 인접 후보. 2갈래면 1개, 3갈래면 2개. 오답끼리도 서로 달라야 함. 0·음수·같은 값 제외. D9 는 이 합집합을 기준으로 전수 검사한다.
- **영단어**: 같은 학년·같은 품사 뜻에서 추출, 정답 뜻과 첫 글자 다른 것 우선(한눈에 구분되되 «생김새»로 못 맞히게). 단어→뜻, 뜻→단어 두 방향을 50:50.
- 문항 반복 규칙: **무작위 출제**에서는 직전 5문항과 같은 문항 금지. **복습 큐 재출제(§1-3-6)는 이 규칙의 예외**이며 우선한다(3문항 뒤 재출제는 의도된 반복).

### 1-3-6. 적응형 출제 (SRS-lite)
- 세션 복습 큐: 틀린 문항을 `[3, 7, 15]` 문항 뒤에 재출제, 3회 정답 시 큐 졸업(이번 판만).
- 영속 오답노트: `BOX_DAYS=[1,3,7,16]`, `MAX_BOX=4`, localStorage. 약점 항목 출제 가중 **최대 3배**(더 자주, 더 어렵게 X).
- 화면 문구 분리: «👍 오늘은 통과!»(세션) ≠ «🎓 완전히 내 거!»(영속 박스 4). 배지는 영속 박스를 읽는다.

  - 🔴 이 항목이 생긴 이유: 21개 게이트가 초록불인 채로 «발판을 누르라»는 말이 어디에도 없는 빌드가 배포됐다. 아무도 「설명이 있는가」를 재지 않았다.
- 해당 없음: 투사체 실체(4-0b-5) · 게임 시계 배속(4-0b-7, 배속 없음) · 난이도 캐릭터 라운드로빈(대전 아님, D10 이 대체).
- [ ] D37. **오늘의 계단은 날짜가 같으면 어디서나 같은 판이다** — `날짜(KST)+과목` 시드로 두 번 만든 판의 목표층·오늘의 규칙·문항 순서가 **바이트로 같다**. 날짜가 하루 다르면 달라진다. 서버도 계정도 쓰지 않는다.
  - 🔴 왜 게이트인가: 「전국이 같은 판」은 눈으로 확인할 수 없다 — 기기가 하나뿐이라서. 결정론이 깨지면 아무도 모르는 채로 「오늘의 계단」이 그냥 무작위 판이 된다. (`tools/qa-retention.mjs` · `tests/daily.test.js`)
- [ ] D38. **구간 해금이 건너뛰기로 열리지 않는다** — 앞 구간을 완주하지 않으면 다음 구간은 잠겨 있다. 저장 데이터를 손으로 고쳐 넣어도(`sanitize`) 잠금이 유지된다.
  - 🔴 localStorage 는 신뢰 경계 밖이다(D12 와 같은 원칙). 해금을 화면에서만 막으면 막은 게 아니다.
- [ ] D39. **압박 문구가 화면에 없다** — 렌더된 DOM 전문에 `연속 끊`·`사라집`·`초 남았`·`지금 안 하면`·`마지막 기회` 가 0건.
  - 🔴 왜 기계가 재는가: 재방문 장치는 **한 줄만 잘못 써도** 강박 장치가 된다. 「이번 주 3일 남았어요」와 「3일 못 채우면 사라져요」는 코드가 같고 문구만 다르다. 근거·조사 원문 = `docs/RESEARCH-retention.md` §3(OECD 아동 다크패턴).
- [ ] D40. **종료점이 보인다** — 결과 화면에 「오늘 할 만큼 했어요」 경로가 실재하고, 탭 타깃 ≥44px 로 눌린다.
  - 🔴 조사가 지목한 다크패턴 중 하나가 「자연스러운 종료점을 없애는 것」이다. 그래서 **그만두는 길을 게임이 먼저 제시한다.** 이 항목은 다른 게이트와 방향이 반대다 — 더 하게 만드는 게 아니라 **그만둘 수 있게** 만드는 것을 잰다.
- [ ] D41. **제목이 원작 상표를 비껴간다** — `<title>`·meta description·manifest 어디에도 「무한」과 「계단」이 5자 이내로 붙어 있지 않고, `Infinite Stairs` 가 0건이다.
  - 🔴 두 낱말을 각각 금지하지 않는다 — 「계단」은 이 게임의 실체다. 문제는 **둘이 붙는 것**이라 거리를 잰다. 이 규칙은 `docs/RESEARCH.md` 가 처음부터 적어 두고도 지켜지지 않던 항목이다: **문서에만 있는 규칙은 지켜지지 않는다.** (`tools/qa-retention.mjs`)
- [ ] D42. **과목을 늘려도 배선이 새지 않는다** — `SUBJECTS` 의 모든 낱말 과목이 ① 자기 낱말 풀을 갖고(둘이 같은 배열을 가리키지 않는다) ② 은행 id 가 과목 이름을 달고 나오며 ③ 숙련도가 쌓이고 `sanitize` 를 통과하며 ④ 120문항을 뽑아도 보기가 겹치거나 비지 않는다.
  - 🔴 왜 「국어가 되는가」가 아니라 「전부가 되는가」로 적는가: 과목 추가는 풀·숙련도·저장·음성 **네 곳**을 동시에 건드리는데, 한 곳을 빠뜨려도 화면은 멀쩡히 돈다. 새 과목이 조용히 남의 낱말 풀을 쓰거나, 숙련도가 안 쌓여 「아직」으로만 보이거나, 한글을 영어 음성으로 읽는다 — 셋 다 **고장이 아니라 오답**으로 나타나서 가장 늦게 발견된다. 그래서 과목 목록을 순회하는 형태로 적어 **다음 과목이 자동으로 검수 대상이 되게** 한다. (`tests/korean.test.js`)
- [ ] D43. **가장 긴 보기가 화면에 들어간다** — 360px(지원 최소 폭)에서 과목마다 «그 과목의 가장 긴 보기»만 모아 2·3갈래를 만들어 그렸을 때, 어떤 보기도 2줄을 넘지 않고 글자가 18px 이상이며, 보기끼리 겹치거나 화면 밖으로 나가지 않고 탭 타깃이 44px 이상이다.
  - 🔴 뽑기로는 못 잡는다: 한 판 40문항을 돌렸더니 가장 긴 보기가 7자였다(12자짜리가 3갈래로 뽑히는 조합이 안 나온다). 그래서 최악의 조합을 **만들어서** 잰다 — 통과하면 그보다 나쁜 조합은 데이터에 없다.
  - 🔴 겹침만 재면 안 되는 이유: 3줄짜리 상자는 **보기끼리는 안 겹친 채** 발판을 통째로 덮어 「발판을 밟는다」는 모양을 없앤다. 겹침 0으로 통과시켰다가 스크린샷에서 발견했다 — **줄 수**가 이 게이트의 핵심이다.
  - 🔴 이 게이트가 데이터 상한을 정한다: 3갈래 칸 폭 105px 에서 18px 하한을 지키며 두 줄에 들어가는 한글은 8자까지 — 그래서 `check-data` 의 `K_MAX = 8` 이다. 「화면에 들어간다」와 「읽힌다」는 다른 조건이고, 글자를 더 줄여 넣는 대신 데이터를 줄인다. (`tools/qa-choice-fit.mjs` · `src/core/balance.js` `CHOICE_FIT`)

## 1-9. 성능 예산
- **참조 기기(고정)**: 모바일 = Samsung Galaxy A34 5G(2023, Android 14, Chrome 최신 안정판, 1080×2340, DPR 2.625) — 보유 기기가 다르면 승인 단계에서 SKU 를 교체해 고정한다 / 데스크톱 = macOS Chrome 최신 안정판 1920×1080.
- **최악 장면**: 층 전환 카메라 이징 + 발판 3개 등장 + 스파클 12 + 불꽃 트레일 40 파티클 + 하늘 크로스페이드 + HUD 갱신 동시.
- **합격선(등급형, L-093)**: 데스크톱 P95 프레임 간격 ≤ 17.5ms(60Hz 등급), 모바일 ≤ 34ms(30Hz 등급) — 「최악 장면에서 쟀다」를 로그로 단언. 평균 fps 로 적지 않는다.
- **번들**: 초기 로드 ≤ 3MB(**gzip 전송량 = 첫 화면→첫 문제까지 HAR transferSize 합**), 번들 전체 ≤ 8MB. 🔴 **온디맨드 콘텐츠(`assets/say` 낱말 발음 943개)는 번들과 «따로» 잰다** — 문제당 4KB 를 하나씩 받는 자산이라 합산하면 «받지도 않는 3.8MB» 때문에 빨간불이 켜진다. 대신 온디맨드에도 상한(6MB)을 두고, 「첫 문제 전에 0건 전송」을 게이트가 직접 확인한다. 테마 에셋은 해금 시 지연 로딩(HAR 에 없어야 한다).
- **드로우콜 경고선**: 최악 장면 ≤ 60 — 최악 장면 스크립트에서 렌더러 드로우 카운터를 프레임마다 읽어 최대값을 로그 단언(D25).
